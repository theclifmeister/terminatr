## Before you update

Nothing to do: the protocol is unchanged since v0.28.0, so there is no need to restart the server for this release. Relay operators can update with `sudo tm relay update` as usual.

## What's new

- **Run a relay with Docker, without cloning the repository.** Each release now has a `tm-relay-docker.tar.gz` download (at `releases/latest/download/tm-relay-docker.tar.gz`). It holds the Dockerfile, the compose files, the Caddyfile and a README, with the compose files set to that release's version.
- **Ready-made relay image.** Each release publishes `ghcr.io/theclifmeister/tm-relay:<tag>` for amd64 and arm64 (and `:latest` for full releases). The compose files pull it by default, so nothing is built on your machine. Building the image yourself is still possible: the compose files keep the `build:` option, commented out.
- **A relay on an IP address with no domain.** The new `compose.selfsigned.yaml` runs a relay with its own key, so it needs no domain and no certificate authority. It keeps the key in `./state` and listens on port 8443, which leaves port 443 free on a NAS. Set `RELAY_IP`, and `RELAY_USER` if your NAS folders belong to another user (for example `1026:100` on a Synology), in a `.env` file. It has the same hardening as the other compose files.
- **Relay settings in `.env`.** `RELAY_IP`, `RELAY_HOST`, `RELAY_USER` and `TM_VERSION` are read from `.env` by all the compose files.
- **Relay docs.** The Docker section of the operations guide is rewritten: download, self-signed, ACME, your own certificates, upgrading, building yourself and NAS setups.

## Fixes

- The info panel next to a paired server's pane no longer says "Read-only" when you can type in the pane. In a writable pane it says that keys go to the server's session. If the link to the server is down it says the server is offline and keys aren't sent. A view-only pane still says read-only.
- The notes of a release now appear on its GitHub release page. v0.28.0 was published with an empty description.
