## Before you update

- **Run `tm server restart` after updating.** This release speaks protocol 18. Until the server restarts, the new console can't talk to the old server, and the dashboard reads project files itself.
- **Relay operators:** update with `sudo tm relay update` (or `--force` from a dev build).

## What's new

- **Faster dashboard.** The server now sends the dashboard each project's threads, reports, inbox, badges and links, so the dashboard no longer reads every project's files each second.
- **Relay limits.** The relay closes idle and slow connections and limits connections per address and in total. It also caps rooms waiting for a partner, bandwidth (`--total-bandwidth`, per room and in total), pings, and update requests. Its connection limit follows its memory limit, and the systemd unit and Docker image set `GOMEMLIMIT`.
- **Relay privacy.** The relay's log no longer records client addresses unless `--log-ips` is set, and `/healthz` no longer shows the tm version. The docs describe what a relay can see.
- **Plain text in your terminal.** tm removes control characters from text written by agents, mods, relays and paired servers before showing it.
- **Clearer mod consent.** Installing or enabling a mod now lists what it changes for agents: policies it replaces, rules it adds, agent manifests and task templates. A mod that changes any of these is no longer labelled "safe". Rules, templates and agent manifests with hidden characters are refused.
- **Guard.** Braced shell variables such as `${NAME}` and PowerShell's `${env:NAME}` are now checked by the credentials rule.
- **Windows.** Agents installed through npm (such as codex) start through node directly, so their arguments reach them unchanged. codex's sandbox checks now work with an npm install. On Windows, codex can't limit a coordinator's network to tm's socket, so the coordinator's network is off (gh, az and git fail in its sandbox and go to auto-review). It keeps its file limits and its connection to tm, and `tm doctor` reports how the network is off.
- **Linked projects across paired servers.** Settings › Linked projects now lists the projects each paired server shares, in one group per server. Press `enter` on a row to step through off, both, send and receive for your side of the link. The other-side column shows what that server's messages say, such as `linked back both ways`, `takes ours` or `refuses ours`.
- **Link requests.** You can ask a paired server's user to link a project with yours. In Settings › Linked projects press `r` on the project, then `y`, or run `tm project link acme mini/api --request`. Your side is set first. The other server shows `1 link request waits` under NEEDS YOU, and its user accepts with `A` in the Messages tab or `tm link accept R-… [both|send|receive] [--ask|--no-ask]`, or declines with `x` or `tm link decline R-…`. Accepting changes only that server's own side. The answer comes back to you, and the Settings column shows `asked, no answer yet`, `accepted: both ways`, `declined`, `request expired` or `request not delivered`. One request can wait per pair, and a server takes at most 5 requests an hour from one other server. Requests expire after 7 days. Older servers refuse a request cleanly, and their user links by hand.
- **Settings popup.** The last row of a tab now scrolls the closing note into view, including the All projects tab, when the window is short.
- **Help on every command.** `-h` and `--help` on any subcommand print its usage and exit 0, for example `tm session keys --help`. They used to say `unknown flag --help`.
- **Installs.** `install.sh` and `tm relay update` keep `/usr/local/bin/tm` at mode 0755 under a strict umask.

## Changed behaviour

- `tm session keys ID text --enter` now presses Enter. Text that starts with `-` must follow `--`, as in `tm session keys s-1 -- ls -la`.
- A bad flag on server, session, agent, watch, attach, doctor and update commands now prints `tm <command>: unknown flag …` instead of a list of defaults.
- A mod's `agents/<name>.toml` named after a built-in agent (claude, codex) is shown on the consent as replacing how tm starts that agent.

## Fixes

- A thread created from outside the server could be missing from the sidebar and dashboard for up to 30 seconds.
- `tm server start` no longer fails when another start wins the race: it waits for the server that is starting.
- Many internal clean-ups, with no change in behaviour: one table for safety settings, a method table in the server, and smaller TUI, CLI and mod files.
